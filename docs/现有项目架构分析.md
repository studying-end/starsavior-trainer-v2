# Star Savior Trainer — 现有项目架构分析（迁移存档）

> 用途：为新建同类项目（同游戏、同功能、重构）提供架构依据与迁移清单。
> 来源：2026-06-27 对 `d:\chengfeng` 的全面摸底。配套坑清单见同目录《现有项目历史坑台账.md》。

## 1. 项目本质与技术栈

- **本质**：Star Savior（PC 客户端）训练自动化脚本。架构核心是**单屏状态机**（ADR-0001）：把游戏视为状态机，每帧识别当前画面类别，只跑匹配该画面的策略，避免"在错误的画面点了看似合理的按钮"。
- **闭环**：截图 → OCR/视觉识别 → 状态机决策 → 鼠标点击。
- **规模**：`starsavior_trainer/` 主包 ~6275 行 + 148 单元测试。
- **技术栈**：`pyautogui`（鼠标合成）+ `PaddleOCR 2.7.3 / paddlepaddle-gpu 3.0.0b2`（GPU OCR）+ `OpenCV 4.5.5`（HSV 检测）+ `Pillow`（裁剪/缩放）+ `Flask`（Web UI）+ 原生 `ctypes`（Windows 窗口截图/前台切换/底层 mouse_event）。

## 2. 核心设计契约（新项目必继承）

**OCR/CV 永远只产生 Observation，绝不直接决定 Action。** 识别层与决策层解耦——这是代码注释反复强调的设计契约，是稳定性根基。
- `classifier` 不知道 payload 长啥样；`policy` 不直接读像素。
- `screens/__init__.py` 的注册表是**唯一调度枢纽**：classifier 的画面匹配、policy 的 decide、live_loop 的 payload 读取，三处统一走注册表，**加画面只动一处**。

## 3. 模块职责（按层）

### 3.1 视觉识别层（截图 → Observation.payload）
| 文件 | 行 | 职责 | 关键要点 |
|---|---|---|---|
| capture.py | ~299 | 截游戏窗口 | DPI 感知 `SetProcessDpiAwareness(2)` 必须先调；**PrintWindow+PW_RENDERFULLCONTENT(2)** 抓被遮挡/未聚焦的 Unity 硬件加速窗口（ImageGrab 做不到）；客户区缩放到目标分辨率（默认 2560×1440）；`activate_window` 用 **AttachThreadInput** 绕过 Windows 反偷焦 |
| ocr.py | ~167 | OCR 引擎抽象 | `OcrEngine` Protocol；`NoopOcrEngine`（管线测试）；`PaddleOcrEngine` PP-OCRv4_mobile，**兼容 PaddleOCR 2.x/3.x/3.5 三种返回格式**；禁 oneDNN/PIR；`read_lines` 返回带 bbox 的行（角色列表滚动半行偏移用） |
| vision.py | ~248 | 颜色/像素检测收口 | RingColorDetector（蓝/金/彩虹环）、BlueButtonDetector（覆盖率 0.03、饱和度 0.18-0.30）；14 个颜色阈值常量。**框架通用，阈值是游戏特定的** |
| classifier.py | ~784 | 画面分类（21 Screen） | `classify_by_ocr`（**两遍加速**：先 OCR 26 个 fast anchors，不命中再全量 ~54 区域，单帧 5-6s→<1s）；`classify_by_blue_button`（纯颜色无 OCR）；`classify_hybrid`（OCR+蓝键兜底，**实跑默认**）；大量 `_has_X_signature` 消歧函数（踩坑沉淀） |
| screen_reader.py | ~1557 | OCR 文字→类型化 payload | **项目最大文件**，混了 OCR 基础设施/文字工具/19 画面 parser/颜色别名。拆分见 §5 |
| image_regions.py | ~35 | 裁剪基础 | crop_region / export_region_crops（标定）/ draw_region_overlay（核对） |

### 3.3 决策执行层（Observation → Action）
| 文件 | 行 | 职责 | 要点 |
|---|---|---|---|
| policy.py | ~828 | 决策引擎 | `PolicyConfig`（所有阈值/坐标集中）；`TrainerPolicy` **大量"两步确认"状态机**（_pending_relic/_pending_blessing/_pending_rest/_pending_commission 记住"上帧点了啥这帧直接确认"，防 OCR 抖动死循环）。拆分见 §5 |

### 3.4 检视器（项目最有特色的设计）
**核心模式**：有些游戏信息只在"选中某项后"才显示在中央详情面板，所以检视器通过"点开→读→点开→读"多帧循环收集信息再决策。在 live_loop 里优先于 policy 调用，返回 None 才回落。
| 文件 | 职责 | 要点 |
|---|---|---|
| training_inspector.py ~96 | 逐张点开训练卡读增益 | 支援卡头像每回合随机；点力量/体力/韧性各一次读 +N，选最高的；**任意一张失败率≥阈值立即放弃其余去休息**；两步确认不依赖 OCR |
| commission_inspector.py ~89 | 逐个点开委托读建议等级 | 列表只显示阶名，建议综合等级(RANK 17)只在选中后中央显示；选"建议等级≤角色 RANK+3"的最高阶 |
| shop_inspector.py ~101 | 逐个点开商品读效果 | 按效果关键词买（回复体力/潜质点退还）；**限购 1 件买完即退** |
| blessing_inspector.py ~90 | 同值祝福卡读子祝福数 | 逐个点击读详情面板子祝福数选最多；**悬停不刷新面板必须点击** |

## 4. 数据流（一次 live_loop 迭代）

1. **急停检查**（鼠标 4 角，margin=120，优先于一切）
2. **暂停检查**（F9 热键，trigger_on_release 防翻转）
3. **截图** capture_window → PrintWindow 抓客户区，缩放 2560×1440
4. **缩放区域** scale_region_profile
5. **分类** hybrid(默认)/blue-mode/paddle/noop
6. **UNKNOWN 处理**：连续 ≤4 帧点屏幕中心推进（过场/加载），>4 帧 pause
7. **parse payload**：走 HANDLERS 注册表；角色列表特殊走 bbox 定位
8. **回合追踪**：TRAINING_HUB 时 observe_date + 读 "RANK 21" 更新 character_rank
9. **决策**：先对应检视器，返回 None 才 policy.decide
10. **重复点击防死循环**：CHARACTER_SELECT 连续 3 次相同点击→强制 pause
11. **执行**：执行前**再次**检查 4 角急停（OCR 耗时数秒，顶部检查会被 execute 的 moveTo 覆盖）→ activate_window → map_action_to_rect → execute
12. **智能睡眠**：过场画面 0.35s 连点；TRAINING_SELECT 0.5s；其他 --interval(默认 3s)

## 6. 通用可复用 vs 游戏特定（迁移清单）

### ✅ 通用可复用（新项目直接搬）
capture.py（纯 Windows 通用）、ocr.py（PaddleOCR 多版本抽象）、**vision.py 的检测框架**（阈值需重标定）、regions.py、image_regions.py、executor.py（急停/hover_move/drag_scroll/map_action_to_rect，对忽略合成输入的 Unity 游戏尤其通用）、logging_setup.py、models.py 的结构（Rect/Action/Observation/GameState）、screens/base.py（ScreenHandler 协议）、manifest.py/fixtures 结构、live_loop 循环骨架、**inspector 设计模式**。

### ❌ 游戏特定（新项目需重写）
21 个 Screen 枚举、所有区域坐标(config/regions/*.json)、所有 OCR 锚点文案、所有 _has_X_signature 消歧逻辑、policy 全部决策规则、config/characters.json+events.json、检视器的具体 inspect_attrs/shop 关键词、vision.py 颜色阈值、PolicyConfig 硬编码按钮坐标。

## 7. 配置与素材

- **config/regions/2560x1440.json**（主配置，330+ 区域）：`{name,resolution,regions:{"区域名":[x,y,w,h]}}`。最游戏特定的资产。另有 1920x1080、2048x1190 两份。
- **config/characters.json**：`{_attribute_rule, _profile_mapping, characters:[{name,class,attribute,profile,variant?}]}`，45+ 角色。**name 必须等于 OCR 清洗后的名字**（最右 2+ 汉字）。
- **config/events.json**（22 事件）：`{events:[{title,aliases,options:[{recommended_profiles,choose_option}]}]}`。部分标题与实机 OCR 对不上→回退关键词。
- **config/relic_combos.json / event_timeline.json**：无代码加载（STATUS.md 标注）。
- **screenshots/**：实跑诊断快照，**被 .gitignore 忽略**（丢失不可恢复，风险点）。
- **examples/demo_manifest.json**、**prototypes/decision_loop.py**（抛弃式原型）、**tools/_*.py**（一次性诊断脚本）。

## 8. 入口与运行

| 入口 | 功能 |
|---|---|
| start_webui.bat | 设 CUDA PATH → Flask → http://localhost:5000（局域网可访问） |
