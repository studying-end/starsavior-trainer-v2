# Star Savior Trainer — 历史坑台账（迁移存档）

> 39 个已踩/待解决的坑，按类别整理。**新项目应在架构上提前规避**，不要重踩。
> 来源：代码注释 + STATUS.md + TODO.md + git log。配套架构见《现有项目架构分析.md》。

## A. 分类误判（画面混淆 → 在错的画面点了按钮）—— 11 条

1. **旅程起点标题被多画面共享**（character_select/blessing_setup/journey_start 都 OCR 出"旅程起点"）→ 纯 OCR 永远解析成 character_select，bot 在祝福画面滚角色列表找不到目标（"卡在祝福"）。**修**：classify_hybrid + classify_journey_origin_by_visual（按内容密度消歧）+ _looks_like_journey_start。**规避**：新项目从 outset 用 hybrid（OCR+视觉双信号），不依赖单一标题。
2. **EVENT_CHOICE 与 DIALOGUE 共享"旅程事件"标题** → 对话被当事件，policy pause。**修**：_has_real_event_options 扫 option_2-4 有真实文本才算。**规避**：事件判定要求多选项都有内容。
3. **TRAINING_SELECT 被误判 SHOP**（D-DAY 卖"保护训练的书"）→ 死循环。**修**：_has_training_select_signature 要求 ≥2 张卡匹配训练名。
4. **D-DAY 交易(SHOP)被误判 BATTLE**（坐在评鉴战背景上）→ **修**：_has_shop_signature 用唯一"刷新"按钮+商品内容。
5. **REGION_MOVE(列车月台)被误判 RELIC_CHOICE** → 中心点立绘不动。**修**：_has_region_move_signature（地区移动+列车月台双锚点）。
6. **基础评鉴战确认框被误判 EVENT_FAST_FORWARD**（都有左下蓝键）→ **修**：_has_battle_signature（跳过战斗+评鉴战/委托标题）。
7. **委托确认框被误判 EVENT_FAST_FORWARD** → **修**：_has_battle_signature 同时接受"委托"。
8. **委托选择被误判 TRAINING_HUB**（hub 也有"委托"按钮）→ **修**：_has_commission_select_signature 要求唯一"接受"按钮。
9. **REWARD 弹窗被误判 CHARACTER_SELECT** → 中心点击死区+角色滚动找不到。**修**：REWARD 独立 Screen+priority=2 早检查+唯一"点击以继续"。
10. **误触 GAME_MENU 弹窗**（指南/选项/重新观测/观测结束）→ 中心点会触发"重新观测"重开局。**修**：GAME_MENU 独立 Screen+priority=2+只点右上角✕。
11. **BLESSING_CHOICE 误判**（与 INITIAL/CHARACTER_SELECT 共享蓝键）→ **修**：_has_blessing_choice_visual_signature（确认键蓝+档案区内容密度双条件）。

> **A 类总教训**：每个易混淆画面都要一个 `_has_X_signature` 多信号消歧函数；priority 高的"陷阱画面"（REWARD/GAME_MENU）独立 Screen 且早检查。

## B. 死循环（OCR 抖动导致两步确认翻转）—— 5 条

12. **遗物两步确认翻转**：selected_name OCR 不可靠，每帧重评"最佳"在近分卡间翻转。**修**：_pending_relic 记住上帧点的卡，下帧直接确认。
13. **祝福两步确认翻转**：同值卡 selected_name 模糊。**修**：_pending_blessing；**悬停不刷新面板必须 click** → 诞生 blessing_inspector。
14. **角色选择两步确认翻转**：左面板 selected_name 对某些角色不可靠。**修**：_char_pending_confirm。
15. **角色列表单向滚动漏掉上方目标**。**修**：双向滚动（先下、半程/到底反向上，cap=30，只反转一次防振荡）。
16. **training hub↔training_select 永久循环**（全失败率过高→pause→hub 又进训练）。**修**：_needs_rest 单次标志，全过高时点返回箭头回 hub，hub 消费此标志直接去休息。

> **B 类总教训**：所有"选 A→确认 A"的两步操作都要 _pending_X 状态记忆；列表搜索要双向 + 重复点击计数防卡。

## C. 急停 / 安全（夺回控制权）—— 3 条

17. **F12 热键被 Steam 截图吞掉** → 改 F9（trigger_on_release=True 防按键重复翻转）。
18. **键盘热键在管理员/Steam 窗口失焦时收不到** → 鼠标 4 角急停（每迭代顶部+execute 前各查一次，margin=120）+ pyautogui FAILSAFE。
19. **execute 的 moveTo 会把鼠标从角里拽回游戏目标** → 急停在 execute **前**再查一次。

> **C 类总教训**：急停要做双保险（热键+鼠标角），且在耗时 OCR 之后、execute 之前再查一次。

## D. Unity 游戏输入特性 —— 4 条

20. **Unity 忽略合成鼠标滚轮** → _drag_scroll 用底层 mouse_event 相对位移模拟真拖拽。
21. **pyautogui moveTo 不被识别为悬停** → _hover_move 用 mouse_event 滑入+停留 0.4s 刷新详情面板。
22. **Unity 只在活动窗口处理鼠标** → activate_window（AttachThreadInput 绕反偷焦）必须在 execute 前。
23. **游戏必须前台才能收滚轮** → 截图用 PrintWindow（不需前台），点击前必须 activate。

> **D 类总教训**：对 Unity 类硬件加速游戏，所有悬停/拖拽都用底层 mouse_event 相对位移，不用 pyautogui 的 SetCursorPos/scroll。

## E. OCR / 数字解析 —— 6 条

24. **失败率只在选中卡显示**，未选中 fail_rate=None（不是 0%）。**修**：把 None 当"不可冒险"，避免赌 ~99% 失败的卡。
25. **RANK 17 数字贴着字母**，parse_first_int 的负向守卫丢前导 1 读成 7。**修**：专门的 parse_rank_number 不守卫相邻字母。
26. **OCR 把"受"读成"文"**，委托"接受"按钮匹配失败。**修**：匹配前导"接"即可。
27. **OCR 把数字读成 o/l/i/s**。**修**：parse_first_int 容错这些字符当数字。
28. **遗物首轮"烦人的布谷鸟时钟"OCR 乱码**（高亮卡名变形）。**修**：只匹配独特词"布谷鸟"。
29. **OCR 把日期读丢月份数字**（"月下旬"）。**修**：round_tracker 规范化失败返回 None 不前进（避免月份碰撞）。

> **E 类总教训**：数字解析要按场景写专门函数（rank/percent/int 各自容错）；按钮匹配用稳定前缀/独特词，不依赖完整文案。

## F. 截图 / 坐标 —— 3 条

30. **DPI 缩放下坐标错位**（4K 150%）。**修**：_set_dpi_awareness 必须在任何窗口/截图调用前。
31. **PrintWindow 抓全黑帧**（窗口最小化）。**修**：检测全黑回退激活+屏幕抓取。
32. **窗口被遮挡时 ImageGrab 抓错窗口**。**修**：PrintWindow 抓窗口自身像素，与 z-order 无关。

> **F 类总教训**：截图统一用 PrintWindow+DPI 感知+全黑检测回退，不用 ImageGrab。
