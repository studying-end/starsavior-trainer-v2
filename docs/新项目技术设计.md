## 1. 目标

同游戏同功能重构迁移。核心是**单屏状态机**：每帧识别画面类别，只跑匹配该画面的策略。闭环：截图 → OCR/视觉识别 → 状态机决策 → 鼠标点击。

## 2. 架构契约（不可违背，详见 CLAUDE.md）

- **OCR/CV 只产 Observation，绝不直接产 Action**：识别层（classifier/screen_reader）与决策层（policy）解耦。
- **screens 注册表是唯一调度枢纽**：分类、决策、payload 读取三处统一走 `screens.HANDLERS`，加画面只动一处。
- **单屏状态机**：绝不在错误画面点"看似合理"的按钮。

## 4. 数据流（live_loop 单次迭代，12 步）

架构文档 §4，T16 严格复刻：
1. 急停检查（鼠标 4 角，margin=120）
2. F9 暂停检查（trigger_on_release 防翻转）
3. 截图 capture_window（PrintWindow，缩放 2560×1440）
4. 缩放区域 scale_region_profile
5. 分类 classify_hybrid（实跑默认）
6. UNKNOWN 处理（连续 ≤4 帧点中心推进，>4 帧 pause）
7. parse payload（走 HANDLERS；角色列表走 bbox 定位）
8. 回合追踪（TRAINING_HUB 读日期 + RANK 更新 character_rank）
9. 决策（检视器优先，返回 None 才 policy.decide）
10. 重复点击防死循环（CHARACTER_SELECT 连续 3 次相同点击 → pause）
11. 执行前**再查急停** → activate_window → map_action_to_rect → execute
12. 智能睡眠（过场 0.35s 连点 / TRAINING_SELECT 0.5s / 其他 3s）

## 5. 关键数据结构（models.py，T1✓ 已迁）

- `Screen(str, Enum)`：21 画面 + REWARD + GAME_MENU + UNKNOWN。REWARD/GAME_MENU 是 priority=2 早检查的陷阱画面。
- `Rect(frozen)`：x/y/width/height + `.center` 属性。
- `Action(frozen)`：kind(click/move/scroll/pause/skip)/target/reason/confidence/scroll_clicks/**repeat**（>1 时过场连点）。
- 每画面一个 frozen payload：`TrainingChoice.fail_rate:int|None`（None=未选中卡未知失败率，绝不当 0% 赌博）、`CommissionChoice.selected_suggested_rank`、`ShopScene.selected_effect` 等。
- `GameState`：desired_character/desired_variant（同名多形态锁定）/current_round/character_rank。
- `Observation`：screen/confidence/payload/source。

## 6. 模块设计（接口契约）

### 6.1 视觉识别层
- **capture.py [T2]**：`capture_window(hwnd, target_size=(2560,1440)) -> Image`；`activate_window(hwnd)`；`find_window(title) -> hwnd`。DPI 感知须模块加载时即调。
- **ocr.py [T3]**：`OcrEngine` Protocol（`read(image)->list[OcrLine]`、`read_lines(image)->list[带bbox]`）；`NoopOcrEngine`（测试用）；`PaddleOcrEngine`（兼容 2.x/3.x/3.5 返回格式）。
- **vision.py [T4]**：`RingColorDetector.detect(image)->Signal(name=blue|gold|rainbow|none, confidence)`；`BlueButtonDetector.detect(image)->Signal(name=active_blue|inactive)`。阈值常量集中模块顶部，标定后填入。
- **classifier.py [T8]**：`classify_hybrid(image, reader, vision) -> Screen`；`classify_by_ocr`/`classify_by_blue_button`；每易混淆画面配 `_has_X_signature(image, reader) -> bool`。
- **screen_reader 拆分 [T9/T10]**：`ocr_reader.RegionOcrReader.read_all/read_names/read_prefixes/read_where`（带 max_area 过滤）；`text_utils.parse_rank_number/parse_first_int/parse_percent`；`screens/<name>.parse(reader) -> payload`。

### 6.2 决策执行层
- **executor.py [T5]**：`Executor.execute(action, rect_map)`；`PyAutoGuiExecutor`（FAILSAFE+4 角急停+mouse_event hover/drag）；`DryRunExecutor`（测试）；`map_action_to_rect(action, screenshot_rect, screen_rect) -> Rect`。
- **screens/base.py [T6]**：`ScreenHandler` Protocol（`screen`/`priority`/`has_anchor`/`parse(reader)->payload`/`decide(payload, state)->Action|None`）。
- **screens/__init__.py [T7]**：`HANDLERS: dict[Screen, ScreenHandler]`、`ANCHOR_HANDLERS: list[ScreenHandler]`（按 priority 有序）。
- **policy/ [T12/T13]**：`TrainerPolicy.decide(observation, state) -> Action`；`_pending_relic/_pending_blessing/_pending_rest/_pending_commission/_char_pending_confirm` 实例状态防两步确认翻转；`policy/config.py` 集中所有阈值与坐标。

### 6.3 检视器 [T15]
`Inspector.inspect(observation, state, executor) -> Action | None`，在 live_loop 优先于 policy 调用。training/commission/shop/blessing 四个，"点开→读→点开→读"多帧循环。character_rank 解耦传递（坑 #39）。

## 9. 开发流程

**环境**：Python 3.11；`pip install -r requirements.txt`；GPU 需 CUDA PATH（PaddleOCR GPU）。PIL/pyautogui/opencv/flask 已在 requirements。

**测试**：`python -m unittest discover -s tests -t . -p "test_*.py" -v`（stdlib，无需 pytest）。NoopOcrEngine 让管线测试无需 GPU。

**Task Master 推进**：新会话 `next_task` 取任务 → set_status in-progress → 实现迁移 → 跑测试验证 → set_status done。LLM provider 为 claude-code（复用会话，零成本）；若报 PERPLEXITY_API_KEY 缺失，重连 MCP。

**迁移纪律**：通用层原样搬（不改逻辑、不顺手改进）；游戏特定层重写（OCR 锚点按实机校准、阈值标定）；每模块 ≤400 行、嵌套 ≤4 层。
