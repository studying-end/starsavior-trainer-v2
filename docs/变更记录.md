- 改动：ocr.py `PaddleOcrEngine` → `RapidOcrEngine`（use_cuda=True，GPU 失败回退 CPU）；runtime `_create_ocr` / read_regions（`--engine rapid`）/ test_live_loop_helpers 跟改；live_loop `--use-paddle` flag 名保留（web UI 在用）但实际走 RapidOCR，mode_label paddle→rapid；process_manager CLASSIFY_MODES 标签 PaddlePaddle→RapidOCR。**坐标/锚点/迁移代码未动**（坐实根因是 OCR 引擎，非坐标——坑 #34 在 2560×1440 上洗清）。

### OCR 批量化提速（17 倍，满足单轮 ≤30s）
- 实跑发现 classify_hybrid 一次 40s（逐区域 OCR~40 次×~1s），一轮训练 ~5 分钟，不可用。
- 诊断：全图 `read_lines`（ONNX Runtime GPU，1.9s 拿全部 text+bbox）+ 按 region rect 中心点匹配文字，比逐区域 `crop_region + read_text` 快 ~20 倍。
- `classifier_anchors._read_anchor_regions`：per-region OCR → 全图 `reader.read_names`（走 `RegionOcrReader` 缓存）。
- `RegionOcrReader`：所有 `read_*` 共享一次 `read_lines`（`self._lines` lazy 缓存），`read_where` 按 bbox 中心点匹配区域 → 一帧只 OCR 一次全图。
- classify + parse 共享同一个 `reader`：`classify_hybrid`/`classify_by_ocr` 接收 `reader`（`isinstance` 兼容旧 `ocr` 参数）；`live_loop` 创建 `reader`，分类+payload 读共用，parse 复用缓存≈0s。
- onnxruntime GPU 缺 cuDNN 9→CPU（慢 3 倍）→ 装 `nvidia-cudnn-cu13`（cuDNN 9.23）+ `nvidia-cublas-cu13`+`ocr.py` 模块级 PATH 注入→GPU 启用。
- 结果：classify 40s→2.88s、parse 1.91s→0、单帧 ≈2.4s、一轮训练（5-8 帧）≈12-20s **远低于 30s 目标**；137 测试全过。
- 详见 设计方案.md §13。

### 委托选择规则更新：+3 buffer 上限 + 全超退一阶
- **问题**：原 `decide_commission` 上限 = `character_rank`（rank 22 时上限 22），漏掉 rank 24 这种"超自己 2 级但可打"的高阶讨伐 → 实际选 rank 19（≤22 的最高），与用户预期"rank 22 最高能打 rank 25"不符。
- **新规则**：`COMMISSION_RANK_BUFFER = 3`（class 常量）。`limit = character_rank + 3`，doable = `[opt for opt in options if parse_first_int(opt.rank) ≤ limit]`，`best = max(doable)` 取最高。全部委托都超 limit 时退一阶：取所有委托里次高 rank 的（最高那档太硬打不动降一档，比无脑选最低阶更合理）。
- **红字优先级不变**：`has_red_text=True` 的委托仍优先于 rank 比较（红字 = 适合当前角色的委托，游戏 UI 提示），不进 buffer 规则。
- **实机场景**：rank 22 + 三委托 rank 17/19/24（无红字）→ 上限 25，doable={17,19,24}，max=24 → 选 rank 24 ✓（原逻辑选 19）。
- 新增测试：`test_picks_highest_doable_within_rank_plus_buffer`（rank 22 + 17/19/24 → 选 24，含两步确认）+ `test_falls_back_to_second_highest_when_all_exceed_limit`（rank 22 + 26/28/30 → 退一阶取 28）+ `tests/test_commission_full_flow.py` 端到端 5 帧（hub 红字 → 委托选 → accept → 战斗开战 → 战斗确认）+ 红字优先 + buffer 常量。142 测试全过（137→142）。

### OCR 引擎可配置（gpu/cpu/auto） + interval 默认 0.5s
- **OCR 引擎选择**：`RapidOcrEngine.__init__` 加 `engine` 参数（"auto"/"gpu"/"cpu"），`use_cuda` 兼容旧调用方（True→"gpu", False→"cpu"）。
- `cli/live_loop.py` 加 `--ocr-engine {auto,gpu,cpu}` 参数（默认 auto），传给 `_create_ocr(use_paddle, ocr_engine)`。
- `_is_cuda_active()` 检测 onnxruntime 是否真用了 CUDAExecutionProvider；engine=auto/gpu 但 CUDA EP 不可用时发 RuntimeWarning（提示用户 onnxruntime CPU 版本仍装着，需 `pip uninstall onnxruntime` 让 onnxruntime-gpu 接管）。
- 保留 onnxruntime 不卸载（用户要求）：两个包同时装时 engine=auto 自动检测，CUDA EP 不可用回退 CPU。
- `--interval` 默认 3.0s → 0.5s（live_loop 同步架构，interval 只是帧间等待，不影响 OCR；总延迟 = OCR + 0.5s + 决策 <1ms）。

### §22.14 事件自动入库（live_loop 集成 + 默认点第1选项）
- **需求**：事件模板库（已存在 events.json 22 事件）+ 事件自动入库。事件是旅途中随机出现的，不像技能/商品可提前入库 → **集成到 live_loop**（运行中遇到未入库事件自动入库），不写独立脚本。新事件入库后**默认点第1个选项**让脚本继续运行。
- **设计决策**（已确认）：live_loop 自动入库（决策层 `_event_db_choice` 内触发）+ 入库写规则（`default_rules choose_option:1`，走第1级 db_choice 选第1个，不污染 fallback）。
- **改动**：
  - [event_db.py](file:///d:/starsavior-trainer-v2/starsavior_trainer/policy/event_db.py)：加 `find_event_exact`（精确名查找，判"是否已入库"，不用模糊匹配）+ `save_event`（新事件入库，写 `default_rules:[{profile:"default",choose_option:1}]` + options 文本 + status:"auto_inserted"；已存在精确名不覆盖，保留用户手填规则）+ `_clear_cache`（save 后清 `_EVENT_DB_CACHE` 重读）。
  - [policy/event.py](file:///d:/starsavior-trainer-v2/starsavior_trainer/policy/event.py) `_event_db_choice`：`_match_event` 返回 None 且 `find_event_exact` 也 None（确认未入库）→ `save_event`(title, options_text, choose_option:1) → 清缓存重读 → 重新 `_match_event` 命中 → `_event_recommended_index` 返回 1 → 选 options[0]。未入库→入库+选第1个在同一帧完成。
- **理由**：
  - **集成到 decide_event 不写独立脚本**：事件随机出现，独立脚本不现实（用户无法预知何时跑）。decide_event 是事件决策唯一入口，在此自动入库最自然（同 shop_inspector 自动入库商品模式）。
  - **入库写规则而非改 fallback**：走第1级 db_choice（最干净），不污染第3级关键词 fallback（保留给已入库但无规则的事件）。
  - **精确 find 不用模糊**：判"是否已入库"用精确名（`find_event_exact`），避免模糊匹配（`_match_event` 阈值0.6）误判已入库。
  - **save 不覆盖**：已入库事件保留用户手填规则（同 skill_db priority 语义），只入新事件。
- **测试**：`tests/test_event_db.py` 8 个（find_event_exact 3 + save_event 3 含不覆盖/清缓存 + decide_event 自动入库+选第1个 2）。295 → 303 全过。
- **非纯迁移**：事件库自动入库机制（save/find/清缓存）+ decide_event 自动入库逻辑。
- 详见 设计方案 §22.14。

- **问题**：ocr.py PATH 注入用 `_m.__file__`，但 nvidia.* 是 PEP 420 命名空间包（无 __init__.py），`__file__` 为 None → `os.path.dirname(None)` 抛异常被 except 吞掉 → cublasLt/cudnn bin 目录未加入 PATH → onnxruntime CUDAExecutionProvider 创建失败回退 CPU（OCR ~7s/帧 vs GPU ~0.6s/帧）。
- **改动**（[ocr.py](file:///d:/starsavior-trainer-v2/starsavior_trainer/ocr.py)）：
  - PATH 注入循环用 `list(_m.__path__)[0]` 替代 `os.path.dirname(_m.__file__)`（命名空间包用 __path__）。
  - 注入循环补 `nvidia.cuda_runtime`/`nvidia.cuda_nvrtc`/`nvidia.nvjitlink`（cudart64_12.dll/nvrtc/nvjitlink 依赖）。
  - cu13 路径块同样用 `nvidia.__path__[0]` 替代 `nvidia.__file__`。
- **CUDA 12 依赖链**（onnxruntime-gpu 1.23.2）：nvidia-cublas-cu12(cublasLt64_12.dll) + nvidia-cudnn-cu12(cudnn64_9.dll) + nvidia-cuda-runtime-cu12(cudart64_12.dll，关键缺失项) + nvidia-cufft-cu12 + nvidia-curand-cu12 + nvidia-cuda-nvrtc-cu12 + nvidia-nvjitlink-cu12。系统原仅 CUDA 11.7，onnxruntime-gpu 1.23.2 要 CUDA 12 runtime。
- **验证**：RapidOcrEngine(engine='gpu') 无 "shifted to CPU" warning；OCR 推理 0.59s（vs CPU ~7s，~12x 提速）；识别正确（"距离目标 50 评鉴战胜利..."）；303 测试全过。
- 详见 设计方案 §13（补充）。

### §22.20 头像计数 Bug 修复：count_heads 位置 NMS + auto_collect 去重阈值对齐（用户报告 bug）
- **Bug**：用户删除已入库头像后，脚本运行中仍对已入库头像重复入库 → 模板库存在同一颗头的多个相似模板 → count_heads 对每个模板独立计数 → 同一颗头被计为多个人头（"明明只有一个人头但识别为多个"）。
- **根因**：去重阈值 0.93 > 识别阈值 0.85，存在 [0.85, 0.93) "准重复"区间——auto_collect 判为新头像入库（< 0.93），但 count_heads 判为命中（> 0.85）→ 同一头重复入库 + 重复计数。
- **修复 1 — count_heads 位置 NMS**（[vision.py](file:///d:/starsavior-trainer-v2/starsavior_trainer/vision.py)）：
  - 原逻辑：遍历所有 N.png 模板，每个 > 0.85 就 count += 1（独立计数，不感知位置）。
  - 新逻辑：收集所有模板命中位置 (x, y, score) → 按分数降序 NMS（同位置 dy < 60px 只保留最高分）→ 对 NMS 后的命中检查羁绊达标。
  - `_HEAD_NMS_DY = 60`（同 collect 的 `_HEAD_NMS_DY`，头像间距 109px，60px 足够区分）。
  - 效果：即使模板库有同一颗头的多个相似模板，NMS 合并同位置命中 → count 正确。
- **修复 2 — auto_collect 去重阈值 0.93→0.85**（[collect_head_templates.py](file:///d:/starsavior-trainer-v2/starsavior_trainer/tools/collect_head_templates.py)）：
  - `auto_collect_new_heads` 默认阈值 0.93→0.85；`_is_duplicate` 默认 0.93→0.85；CLI `--match-threshold` 默认 0.93→0.85。
  - 去重灵敏度 = 识别灵敏度，消除 [0.85, 0.93) 准重复入库。同一颗头裁剪稍有偏差也判为重复（不入库）。
- **模板库检查**：现有 6 个作数模板（1/4/5/6/7/10.png）两两匹配分数最高 0.798 < 0.85，无重复，无需清理。
