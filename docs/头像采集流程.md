# 支援卡头像采集流程（截图 → 裁剪 → 去重 → 入库）

本文说明 `collect_head_templates` 工具如何从游戏画面获取**新支援卡头像**并写入模板库 `config/assets/N.png`（纯数字命名，如 `1.png`、`2.png`，不含羁绊进度条），供运行时 [`count_heads`](../starsavior_trainer/vision.py#L259) 做人头计数。旧库 `counting_head_*.png` / `non_counting_head_*.png` 保留为遗留不再使用。

- 入口脚本：[`starsavior_trainer/tools/collect_head_templates.py`](../starsavior_trainer/tools/collect_head_templates.py)
- 截图模块：[`starsavior_trainer/capture.py`](../starsavior_trainer/capture.py)
- 裁剪/区域：[`starsavior_trainer/image_regions.py`](../starsavior_trainer/image_regions.py)、[`starsavior_trainer/regions.py`](../starsavior_trainer/regions.py)
- 区域配置：[`config/regions/2560x1440.json`](../config/regions/2560x1440.json)

---

## 0. 整体管线

```
游戏窗口
   │  ① capture_window()         ← PrintWindow 抓 client 区，缩放到 2560×1440
   ▼
2560×1440 整帧 PIL.Image
   │  ② load_region_profile + scale_region_profile
   ▼
带 training_select_heads_panel 矩形的 RegionProfile
   │  ③ _find_head_instances()    ← 沿 x≈1810 列滑窗扫描（111×93，步长 5）
   ▼
N 个头像实例（loc_score 局部极大值 NMS 定位）
   │  ④ dedup_score 阈值判定      ← 与**作数 N.png + 不作数 non_counting_head_N.png** 比对，阈值 0.93
   ▼
新头像 → {max+1}.png 入库；重复则跳过（含已入库的不作数头）
```

> 头像**不在训练卡 (training_select_card_*) 上**，而在画面顶部右侧的 `training_select_heads_panel` 头像面板内纵向排列成一条"头像列"。每回合哪些槽位填头像、填什么角色都变，故沿列扫描而非固定 y 槽位裁剪。

调用方式：

```bash
# 自动截图（按窗口标题）
python -m starsavior_trainer.tools.collect_head_templates --window-title "Star Savior"

# 用已有截图（跳过截图步骤，便于复核）
python -m starsavior_trainer.tools.collect_head_templates --image screenshots/training_select.png
```

> ⚠️ **前置条件：游戏必须停在「训练选择 (TRAINING_SELECT)」画面**。工具**不校验当前画面类别**，只按 `training_select_heads_panel` 矩形沿 x≈1810 列滑窗扫描——若停在其他画面，扫到的可能是任意 UI，只要灰度 `std≥25` 又不命中现有模板，就会被当作新头像存进 `N.png`，**污染模板库**。
>
> **入库前必做的两道校验**：
> 1. **画面校验**（最关键）——先用分类器确认当前是 TRAINING_SELECT，否则一切后续都无意义：
>    ```bash
>    python -c "import starsavior_trainer.classifier as c, starsavior_trainer.capture as cap, starsavior_trainer.regions as r, starsavior_trainer.ocr as o; s,_=cap.capture_window('StarSavior'); p=r.scale_region_profile(r.load_region_profile('config/regions/2560x1440.json'),s.size); print(c.classify_hybrid(s,p,o.NoopOcrEngine()).screen)"
>    ```
>    输出必须是 `Screen.TRAINING_SELECT`。实测停在 `relic_choice` 等画面时，沿列扫到的全是无关 UI，dry-run 仍会报"新头像"——这是**假新**，绝对不能入库。
> 2. **预览校验**——`--dry-run` 后看 `screenshots/head_crops/slotN.png`（N 为槽位序号）确实是支援卡圆形头像再正式跑。

## ① 截图：`capture_window`（[capture.py:135](../starsavior_trainer/capture.py#L135)）

### 1.1 DPI 感知（前置必做）

模块导入时即调用 [`_set_dpi_awareness()`](../starsavior_trainer/capture.py#L14)，执行 `SetProcessDpiAwareness(2)`（`PROCESS_PER_MONITOR_DPI_AWARE`），失败再退 `SetProcessDPIAware()`。

**为什么必须在任何窗口/截图调用之前做**：显示缩放（如 4K 150%）下，`GetClientRect`/`ClientToScreen` 默认返回**虚拟逻辑坐标**，而 `ImageGrab` 返回**物理像素**。两者不一致会导致裁剪区整体错位。设成 per-monitor aware 后，两套 API 统一到物理像素。

### 1.2 找窗口：`find_window`（[capture.py:181](../starsavior_trainer/capture.py#L181)）

- `EnumWindows` 遍历所有**可见**顶层窗口；
- 标题含 `title_contains`（大小写不敏感子串）的收集为候选；
- 优先**精确匹配**，其次取**标题最短**者（游戏窗口标题通常比 IDE 短，避免误选编辑器）。

### 1.3 抓 client 区：PrintWindow 优先（[capture.py:65](../starsavior_trainer/capture.py#L65)）

关键函数 [`_capture_client_via_printwindow`](../starsavior_trainer/capture.py#L65)，步骤：

1. `GetWindowRect` 取**整窗**尺寸（含标题栏/边框）`win_w × win_h`；`GetClientRect` 取**客户区**尺寸 `client_w × client_h`。
2. `ClientToScreen(0,0)` 算出客户区左上角相对整窗左上角的偏移 `(off_x, off_y)`（=标题栏高度 + 边框宽度）。
3. `GetWindowDC` → `CreateCompatibleDC` → `CreateCompatibleBitmap(win_w, win_h)` 建一张与窗口等大的位图。
4. **`PrintWindow(hwnd, mem_dc, PW_RENDERFULLCONTENT=2)`**：把窗口自身像素拷进位图。flag=2 是 DWM/硬件加速窗口（Unity 游戏）的必备项。
5. `GetDIBits` 配 `BITMAPINFOHEADER`（`biHeight = -win_h` 表**自上而下**行序、`biBitCount=32`、`BI_RGB`），把位图读进 `BGRX` 原始缓冲，`Image.frombuffer("RGB", ..., "raw", "BGRX", ...)` 转 PIL。
6. 从整窗图里按 `(off_x, off_y, off_x+client_w, off_y+client_h)` **裁出客户区**（对无边框/有边框两种模式都对）。
7. 全黑帧检测：`client.convert("L").getextrema() == (0, 0)` → 返回 `None`，通知调用方走兜底。

**为什么用 PrintWindow 而非直接 ImageGrab**：PrintWindow 按 z-order 拷窗口**自己的**像素，无论游戏是否被遮挡/在前台都正确；ImageGrab 只能拍到屏幕上此刻物理显示的像素，被别的窗口盖住就会静默抓错。所以采集本身**不需要抢焦点**。

### 1.4 兜底：屏幕截图 + 裁剪（[capture.py:162](../starsavior_trainer/capture.py#L162)）

PrintWindow 失败/全黑时：

1. [`activate_window(hwnd)`](../starsavior_trainer/capture.py#L226)：用 `AttachThreadInput` 把当前线程输入队列临时挂到前台线程与目标线程，绕过 Windows 的 anti focus-stealing，再 `SetForegroundWindow`（这条路径需要窗口可见）。
2. `ImageGrab.grab()` 抓整屏；
3. 按客户区屏幕坐标 `(pt.x, pt.y, pt.x+client_w, pt.y+client_h)` 裁出。

### 1.5 统一缩放到 2560×1440（[capture.py:167](../starsavior_trainer/capture.py#L167)）

若 client 实际尺寸 ≠ 目标 `(2560, 1440)`，用 `Image.LANCZOS` 缩放。**这一步是后续坐标系的基准**——区域配置 `2560x1440.json` 里所有矩形都基于这个归一化帧，所以采集和运行时用的是同一套坐标。

返回 `(client_img, WindowInfo)`。

## ② 加载并缩放区域配置

### 2.1 `load_region_profile`（[regions.py:18](../starsavior_trainer/regions.py#L18)）

读 JSON，`resolution` 字段 = `[width, height]`；`regions` 里每项是 `[x, y, width, height]`，解析成 `Rect`。

### 2.2 `scale_region_profile`（[regions.py:39](../starsavior_trainer/regions.py#L39)）

若截图实际分辨率 ≠ profile 分辨率，按 `scale_x = target_w / base_w`、`scale_y = target_h / base_h` 等比缩放每个矩形（宽高至少为 1）。由于 ① 已统一缩放到 2560×1440，此处通常直接命中同分辨率、原样返回。

## ③ 沿头像列扫描：`_find_head_instances`（[collect_head_templates.py:126](../starsavior_trainer/tools/collect_head_templates.py#L126)）

头像**不在训练卡上**，而在画面顶部右侧的 `training_select_heads_panel`（2560×1440 下矩形 `[1600, 130, 950, 260]`）内纵向排列成一条"头像列"。几何按面板尺寸比例表达（分辨率变化时随 panel_rect 缩放，标定基准 2560×1440）：

| 几何参数 | 比例（相对 panel） | 2560×1440 下取值 | 说明 |
|---|---|---|---|
| `_HEAD_COL_X_FRAC` | `210/950` | 列 x ≈ 1810 | 头像列 x 固定 |
| `_HEAD_W_FRAC` | `111/950` | 窗口宽 111 | 头像宽 |
| `_HEAD_H_FRAC` | `93/260` | 窗口高 **93** | 缩减高度排除下方羁绊进度条（原 `113/260` 含进度条会导致模板随羁绊值漂移） |
| `_HEAD_SLIDE_STEP` | — | 5px | 沿列滑窗 y 步长 |
| `_HEAD_EMPTY_STD` | — | 40 | 窗口灰度 std 低于此值视为空槽（原 25，远 panel 噪声区 std≈25 会被误判为头像候选，提到 40 干净分离：真头像 std 73-98） |
| `_HEAD_NMS_DY` | — | 60 | 相邻峰值 y 差小于此值合并（NMS） |

**扫描算法**：以 111×93 窗口沿列从 `panel.y` 滑到 `image.h - win_h`（扫描范围扩大到**全图高度**——头像可能超出 panel 底部，panel h=260 容纳不下全部），步长 5px，对每个窗口：

1. 灰度 `std < 40` → 空槽/背景，跳过；
2. 否则同时计算两个分数：
   - `loc_score` = 与**所有模板（旧库+新库）**的最大匹配分，用于定位头像位置（旧库含进度条，但 matchTemplate 仍能定位头像大致位置，分数 0.5–0.9）
   - `dedup_score` = 与**作数 N.png + 不作数 non_counting_head_N.png**的最大匹配分，用于去重判断（避免同一颗头无论作数/不作数反复入库）

**NMS：loc_score 局部极大值法**。在 `loc_score` 曲线上找局部极大值（前后窗口都更高且 >0.3）作为头像候选；相邻峰值 y 差 ≤ 60 时保留更高分者。
> 旧版 NMS 按"相邻窗口 y 差 < 60 合并"有 bug——滑窗步长 5 < NMS 阈值 60 会导致**全列合并成 1 组**，故改成局部极大值法。

返回 `[(slot_idx, Rect, is_dup, matched_file, dedup_score), ...]`，每个 rect 即精确定位到的头像窗口。

## ④ 裁出头像候选：`crop_region`（[image_regions.py:11](../starsavior_trainer/image_regions.py#L11)）

§③ `_find_head_instances` 已用滑窗精确定位每个头像的 `Rect`，main 循环对每个 rect 直接调用 `crop_region(image, rect)` 裁出 111×93 的头像图——**不再有"从训练卡左侧裁正方形头像"的步骤**（旧 `_crop_head_from_card` 已废弃，头像实际在面板顶部头像列上，不在训练卡上）。

可选 `--resize-crop N`（如 64）把头像统一缩放到 N×N（LANCZOS），便于库内尺寸一致；不传则保留 111×93 原尺寸。

## ⑤ 去重判定：`dedup_score` 阈值（[collect_head_templates.py:90](../starsavior_trainer/tools/collect_head_templates.py#L90))

§③ 滑窗过程中已对每个候选窗口算出 `dedup_score`（仅与新库模板的最大匹配分）。去重判定直接用该分数：

- **仅比对新库**：[`_is_new_library_template`](../starsavior_trainer/tools/collect_head_templates.py#L51) 判断 `^\d+\.png$`（纯数字 .png），旧库 `counting_head_*.png` / `non_counting_head_*.png` **不参与比对**（旧库含进度条，裁剪几何不同，比对无意义）。
- `dedup_score >= 0.93`（默认，可 `--match-threshold` 调）→ 判重复，跳过。
- 否则 → 新头像，进入入库。

**为什么去重阈值（0.93）必须高于识别阈值（0.85）**：要满足 `dedup ≥ recog`，否则两边阈值夹出的"中间地带"会出问题。0.93 更严是**双向避险**——

- **不能太低**（false-dup）：把真新头像误当旧头漏存，下次还是采不到。
- **不能贴近 0.85**（false-new）：把与旧头相近的新头另存一份，运行时 [`count_heads`](../starsavior_trainer/vision.py#L259) 用更松的 0.85 会**同时命中**新旧两张模板，把同一颗头数成 2 → 早期游戏选训练直接错。

0.93 比 0.85 高出 0.08 余量，足以把"不同角色的头像"和"同一颗头的重采"分开。

## ⑥ 入库：命名与保存（[collect_head_templates.py:303](../starsavior_trainer/tools/collect_head_templates.py#L303))

- [`_next_template_id`](../starsavior_trainer/tools/collect_head_templates.py#L68)：扫现有新库模板（`^\d+\.png$`）序号，取 `max + 1`（空库从 1 开始）。
- 保存为 `config/assets/{next_id}.png`（纯数字命名，如 `1.png`、`2.png`）。
- 预览路径：`screenshots/head_crops/slot{slot_idx}.png`（slot_idx 为列内序号，与卡片属性无关）。
- `--dry-run`：只写裁剪预览不入库。

> ⚠️ **新库 vs 旧库**：新库 `N.png` 不含羁绊进度条（几何 111×93），是当前唯一使用的库；旧库 `counting_head_*.png` / `non_counting_head_*.png` 含进度条，几何不同，**保留为遗留不删除**，但去重和 `count_heads` 都不再扫它。
>
> 旧版"一律以 `counting_head_*` 入库，需手动改名为 `non_counting_head_*`"的注意事项已废弃——新库不区分作数/不作数，所有头像统一入库 `N.png`，`count_heads` 默认全数（早期游戏假设所有头像都作数）。

## ⑦ 与运行时 `count_heads` 的衔接

[`count_heads(image, search_region=None)`](../starsavior_trainer/vision.py#L271)（[vision.py:271](../starsavior_trainer/vision.py#L271)）：

- 每次**全图** `matchTemplate`（默认 `search_region=None` 全图搜——人头位置每回合变、可延伸到卡片区，限区会把头切边漏匹配）；
- 遍历 `config/assets/*.png`，由 [`_is_head_template`](../starsavior_trainer/vision.py#L256) 过滤 `^\d+\.png$`（**仅新库 N.png**），得分 > `_HEAD_MATCH_THRESHOLD = 0.85` 即该头在场，数命中数；
- 旧库 `counting_head_*.png` / `non_counting_head_*.png` 不在计数集，天然排除（保留为遗留不删除）。

模板目录**每次调用都重新 `glob` + `cv2.imread`**（[vision.py:293-296](../starsavior_trainer/vision.py#L293)，无任何模块级缓存），所以新入库的头像**下一帧即生效，无需重启游戏循环**。工具末尾打印的"请重启"提示偏保守，可忽略（其括注"动态扫描模板目录"本身就和"重启"矛盾）。

调用链：`TrainingInspector._decide_early_game` 逐张点 5 卡 → 选中那张后下一帧 `count_heads(image)` 读其人头（[training_inspector.py:136](../starsavior_trainer/inspectors/training_inspector.py#L136)）→ `decide_early_training` 选人头最多者；全 ≤1 则去住处休息回心情（详见 [设计方案.md §12](设计方案.md)）。
